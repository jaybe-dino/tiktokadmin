# GloveK 어드민 · AI 에이전트 운영 가이드

> 업무 효율 극대화를 위한 자동 에이전트 체계. **정의는 코드(lib/agents.ts) 레지스트리**, **관리·모니터링은 `/agents` 화면**, **실행은 Vercel Cron + 수동**.
> 핵심 원칙: 읽기는 DB 직결, **상태변경·발송 같은 쓰기는 "제안/초안"까지만 — 실행은 사람 승인**(초안함·결재함·Slack 버튼). AI는 요약·제안만, 판정(등급·게이트·정산·견적)은 규칙 엔진.

---

## 1. 필요 에이전트 9종 (왜 필요한가 = 업무 효율)

| # | 에이전트 | 종류 | 스케줄 | 하는 일 | 절감 효과 |
|---|---|---|---|---|---|
| 1 | **일일 운영 점검** | 규칙 | 매일 09:00 | SLA위반·게이트위반·서류단계·미배정·접촉공백 집계 | 매일 아침 "어디가 막혔나"를 사람이 안 찾아도 됨 |
| 2 | **서류 리마인더** | 규칙 | 매일 14:00 | docs 단계 미완 브랜드에 리마인더 **초안** 생성(초안함) | 온보딩 담당의 반복 독촉 메일 작성 제거 |
| 3 | **결제·정산 감시** | 규칙 | 매일 10:00 | 연체·정산 draft·이상치 집계 | 정산 누락·연체 방치 방지 |
| 4 | **인증 만료 감시** | 규칙 | 매일 08:00 | 만료 임박(30일)·미비 인증 → 판매 리스크 알림 | 인증 만료로 인한 판매 중단 사고 예방 |
| 5 | **운영 사이클 감시** | 규칙 | 매일 09:30 | 월중(15일↑) 이행률 미달 알림 | 대행 이행 지연 조기 감지 |
| 6 | **무응답 감시** | 규칙 | 매일 11:00 | 발송 후 3영업일 무응답 → 재접촉 알림 | 리드·고객 이탈 방지 |
| 7 | **미팅 후처리** | AI | 10분~1시간 | 녹음 전사→회의록 요약→팔로업 초안·노쇼 감지 | 미팅당 15~30분 수기 정리 제거 |
| 8 | **주간 자가학습** | AI | 매주 월 09:00 | 퍼널 지표 분석·병목 제언·인사이트 저장 | 주간 리포트·분석 자동화 |
| 9 | **사전분석** | AI | 신규 유입 + 매일 11:30 | 브리프 없는 브랜드 진단 브리프 생성 | 영업 준비(브랜드 리서치) 자동화 |

- **규칙 에이전트(1~6)**: ANTHROPIC 키 없이 즉시 동작. 집계·알림·초안 생성.
- **AI 에이전트(7~9)**: `ANTHROPIC_API_KEY`(요약·제언), 미팅은 추가로 `OPENAI/GROQ_API_KEY`(전사) 필요. 키 없으면 규칙 부분만 동작.

## 2. 어떻게 작동·관리시키나

### 2-1. 관리 화면 `/agents`
- 9종 목록: 종류(규칙/AI)·스케줄·최근 실행·마지막 결과.
- **on/off 토글**: 특정 에이전트 일시 정지(cron이 스킵). *파트장/대표 권한.*
- **[지금 실행]**: 즉시 1회 실행 → 결과 요약 표시(테스트·긴급용).
- **최근 실행 로그**: 시각·트리거(cron/manual)·상태·조치 수·요약.

### 2-2. 자동 스케줄 (Vercel Cron)
`vercel.json`에 등록됨 — 배포 시 자동 적용:
```
/api/cron/agents        매일 00:00 UTC(09:00 KST)  → 9종 전체 실행(비활성 제외)
/api/cron/meeting-process  매시           → 미팅 전사·요약(별도 고빈도)
/api/cron/gmail-sync    매시           → 메일 수집·무응답
/api/cron/cycle-open    매월 1일 02:00 → 사이클 발행
/api/cron/cycle-close   매월 1일 01:00 → 전월 마감·정산 draft
+ 기존: sla-check(매시)·escalate(일)
```
- 개별 실행: `GET /api/cron/agents?key=daily_ops_check&token=<CRON_SECRET>`
- 인증: Vercel Cron은 `Authorization: Bearer <CRON_SECRET>` 자동. 수동은 `?token=<CRON_SECRET>`.
- 더 촘촘한 주기(예: 미팅 10분)는 Vercel Pro에서 cron 세분화.

### 2-3. 안전장치 (거버넌스)
- 에이전트는 **직접 상태변경/발송 안 함** → email_drafts(초안함)·alerts·approval_requests(결재함)로 "제안"만. 사람이 초안함/결재함/Slack에서 승인·발송.
- 중복 방지: 알림은 `alerts UNIQUE(brand_id,kind)`, 리마인더 초안은 기존 draft 있으면 스킵.
- 모든 실행은 `agent_runs`에 기록(감사).
- 비용 가드: AI 호출은 max_tokens 제한. 키 미설정 시 규칙만.

## 3. AI 활용 구조

### 3-1. 계층
```
[에이전트/화면] → lib/ai.ts(공용 Anthropic·모델 env) → 요약·제언·초안
                → lib/stt.ts(Whisper 전사)
                → lib/mcp-tools.ts(도메인 툴) ← MCP 서버·Slack /ask 공유
쓰기는 항상 /api/ops(게이트) 또는 초안/결재 경유
```
- **모델**: `ANTHROPIC_MODEL`(기본 claude-sonnet-5) 단일 지점(하드코딩 제거).
- **결정론(AI 금지)**: 등급(grade)·게이트(gates)·SLA·dedup·견적(computeQuote)·정산. → 규칙 엔진이 판정, AI는 문구·요약·제안만.

### 3-2. 현재 AI가 실제 하는 일 (키 넣으면 즉시)
- 미팅 회의록 요약 + 팔로업 초안(설문 링크 포함)
- 대화맥락 기반 메일 초안(브랜드360 [AI 초안] → 초안함)
- 사전분석 브리프
- 주간 퍼널 제언
- AI 인수인계 요약(담당 변경)
- Slack `/ask`(도메인 툴로 원장 질의)

### 3-3. 로드맵(코드 추가 예정 — 백로그 3부)
QnA 재사용 사이클 · 제안서 AI 커스텀 문구 · 인증 필요서류 AI 가이드 · 사이클 종료 리포트 초안 · RFP 요약 · 화면 컨텍스트 AI 패널 · MCP 서버 배포.
