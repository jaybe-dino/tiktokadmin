# 20 — UI 기능정의서 (Functional Spec)

> **버전 v2.5 (2026-07-31) · 기준 파일: glovek-admin-ui.html (프로토타입)**
> 모든 화면(26)·플로우(7)·전역 시스템의 기능을 화면 단위로 정의한다.
> 각 화면은 `목적 → 진입 경로 → 구성요소 → 액션 표(요소→동작→결과→권한·연동)` 순으로 기록한다.
> 프로토타입은 데모 데이터이며, 실제 동작·API는 각 표의 "연동" 열이 가리키는 문서(01~19)를 따른다.

## 0. 전역 시스템 (모든 화면 공통)

### 0-1. 내비게이션
| 요소 | 동작 | 결과 | 권한·연동 |
|---|---|---|---|
| 좌측 사이드바 메뉴 | 클릭 | `go(id)` — 해당 섹션 표시, 활성 메뉴 하이라이트 | 전 역할. 메뉴 노출은 역할별 필터(12-RBAC) |
| 상단 전역 검색 | `/` 키 또는 클릭 | 브랜드·담당·이메일·사업자번호 통합 검색 | 원장 단일 인덱스(01-DB) |
| 상단 요약 칩(오늘 미팅·SLA·결재) | 클릭 | 해당 화면으로 이동 | 실시간 카운트(04-DASHBOARD) |
| Slack 연결 배지 | 표시 | 봇 연결 상태 | 05-SLACK |

### 0-2. 상태 이동 모달 `#ovl` (원장의 유일한 전진 수단)
| 요소 | 동작 | 결과 | 권한·연동 |
|---|---|---|---|
| [상태 이동] 버튼(브랜드360 등) | 클릭 | 현재→다음 상태 게이트 체크리스트 모달 | 담당자 본인 또는 T2+ |
| 게이트 항목 미충족 | 이동 시도 | **422 차단** — 부족 항목 목록 표시, 이동 불가 | 03-GATES |
| [이동 실행] | 클릭 | 상태 전진(전진 전용) · 스테퍼/배지/게이트 카드 즉시 갱신 · 이력 기록 | state_transitions 로그 |

### 0-3. 범용 모달 `#gmo` (openGm)
제목·본문·확인 버튼·취소로 구성. 계약 등록, 결제 안내, 발송 전 확인, 미팅 제안, 심층분석 등 모든 폼형 액션이 이 모달을 사용한다. [취소]/[✕]는 닫기만, [확인]은 액션 실행 후 토스트.

### 0-4. 발송류 버튼 공통 규칙 〔v2.4 강화〕
"발송·리마인더·안내"가 포함된 버튼은 **절대 즉시 발송되지 않는다.** 클릭 → 발송 전 확인 모달(받는이 / 발신 계정 / 제목 / 본문 textarea) → [승인·발송] → 그때 발송 처리. 발신은 항상 회사 계정(@dinostudio.kr / 지정 번호)만 사용(09-EMAIL §9-C-2).

### 0-5. 기타 전역
| 시스템 | 정의 |
|---|---|
| 토스트 `#toast` | 모든 액션의 결과 피드백. 3초 자동 소멸 |
| 툴팁 `data-tip` | 주요 버튼 호버 시 설명 — 가이드 없이 사용 가능하게 하는 장치 |
| 탭 그룹 | 화면 내 탭(#btabs 브랜드360 · #mtabs 마케팅 · #stabs 발송센터). 탭 클릭 → 해당 패널만 표시 |
| 처리 완료 행 | 워크큐·결재함에서 처리된 행은 `done-row`(회색+취소선+✓)로 바뀌고 버튼 비활성 |
| 드래그앤드랍 | 칸반 카드·캘린더 일정에 적용(각 화면 절 참조). HTML5 DnD |

## 2. 고객

### 2-1. 브랜드(원장) `s-brands`
**목적**: 1 브랜드 = 1 행의 단일 원장. 전 브랜드 검색·필터.
액션: 검색(이름·사업자번호·이메일·전화 — 중복 판정 키와 동일), 필터(상태·등급·담당·날짜 그룹), 행 클릭→브랜드 360, [+ 리드 등록], [CSV 가져오기]→리드 가져오기. 연동: 01-DB(dedup email→phone→biz_no→brand_name), hard-delete 금지(is_test/archived).

### 2-3. 리드 가져오기 `s-leadimport`
**목적**: 대량 CSV·수동 등록의 진입점 + 등록 이후 보호 장치 안내.
구성: CSV 업로드(컬럼 매핑·중복 미리보기) / **날짜 그룹 지정**(등록일 기반 코호트 — 대량 발송 그룹핑에 사용) / 〔v2.4〕 **"🛡️ 등록 이후 가드레일" 카드**: STEP 0 등록 즉시 자동(dedup·담당 후보 배정·브리프 생성) → 당일 담당 수락 → 48시간 첫 컨택 → 7일 방치 차단의 4단계 과정 설명 + [워크큐]·[SLA 모니터] 바로가기 + "어떤 리드도 조용히 사라질 수 없습니다".
액션: [업로드·검증]→중복/오류 리포트→[등록 실행], 개별 등록 폼. 연동: 02-INGEST, 03-GATES.

**목적**: 계약 등록과 결제 확인 관제. **어드민은 결제 안내만 발송 — 수납은 glovek.space가 직접**〔결정〕.

### 6-3. 자산 저장소 `s-assets` — 탭 3개 (#atabs) 〔v2.5 재구성〕
**목적**: 파일·레퍼런스의 단일 색인 + **구글 드라이브 양방향 연동**(UI 설계 — 드라이브에 올려도, 어드민에 올려도 같은 색인).

상단: 드라이브 연결 배너(계정·루트 폴더 GloveK_Assets·마지막 동기화) / [🔄 드라이브 동기화] / [+ 업로드 → 드라이브 저장].

| 탭 | 내용 | 주요 액션 |
|---|---|---|
| 파일 목록 a-files | 전 파일 표 — 출처 배지(드라이브/어드민 업로드)·브랜드·파트·연결 카드·담당. 드라이브 문서(Sheets·PDF 등)도 동일 색인 | 검색·필터(종류/파트/출처), [열기 ↗](드라이브 원본) |
| 레퍼런스 목록 a-refs | 성과 콘텐츠·제안서 템플릿·베스트 사례·외부 링크·가이드 문서. 태그·사용 횟수(첨부·인용된 횟수) | [+ 레퍼런스 추가] 모달(드라이브 파일/URL). Remake Studio 성과 콘텐츠는 기준 충족 시 자동 유입. AI 초안·제안서 작성 시 자동 추천 |
| 드라이브 연동·파트 담당 a-drive | ① 연동 설정: 연결 계정·루트 폴더·양방향 5분 주기·삭제 시 아카이브 + **폴더↔파트 매핑 표**(01_고객~05_운영정산, 폴더에 올리면 파트·종류 자동 분류, 파일명 브랜드 자동 연결) ② **파트별 주요 담당**: 파트(고객/영업/마케팅/온보딩·제품/운영·정산)별 기본 담당 지정 + "지금 수정 중" 실시간 표시 | [담당 지정 저장] |

**담당 규칙** 〔v2.5〕: 로그인한 사용자가 자기 파트의 기본 담당 — 자료를 열어 수정하는 순간 그 사람이 해당 자료의 담당자로 자동 기록(마지막 수정자 = 현재 담당). 파트 기본 담당은 a-drive 탭에서 지정.

**전역 첨부 정책** 〔v2.5〕: 모든 화면의 [📎 파일 첨부]·[파일 선택]은 **자산 선택기 모달**(드라이브 검색 / 최근 파일 / 새 업로드→드라이브 저장)을 통해서만 첨부된다. 원본은 드라이브 1곳, 카드에는 링크만 — 중복 파일 없음. 계약 등록·서류 업로드 등 다른 모달 안의 첨부 버튼도 자산 선택기로 전환된다. 민감서류(신분증·여권·카드정보)는 색인 제외(보안 규약).

## 9. 세부 스텝 플로우 화면 7종 (교육·검증용 — 실제 화면의 스텝별 해설)

각 플로우 화면은 스텝 카드가 잠금(.locked) 상태로 시작하며, 파란 버튼을 눌러야 다음 스텝이 열린다(모든 스텝 실제로 밟기 가능). [↺ 처음부터]로 리셋.

| 플로우 | 내용 | 핵심 규칙 |
|---|---|---|
| ① 리드 유입 f-lead | 메타 광고 → 웹훅 수신 → dedup → 담당 후보 → 수락 → 브리프 | 등록 즉시 STEP 0 자동 실행 |
| ② CSV 대량 등록 f-csv | 업로드 → 매핑 → 중복 리포트 → 날짜 그룹 → 등록 | 중복은 병합, 신규만 생성 |
| ③ 줌 미팅 f-zoom | 예약 → 자동 매핑 → 회의록 수집 → AI 팔로업 초안 → 설문 | 호스트=담당 자동 감지 |
| ④ 게이트·SLA f-gate | 게이트 422 차단 → 보완 → 통과 → SLA 타이머 → 에스컬레이션 | 3중 방어 체험 |
| ⑤ 제안→계약→결제 f-prop 〔v2.4 재작성〕 | **6스텝**: 1 제안서 작성(computeQuote 자동 견적) → 2 할인 결재(조건부 — 20% 이하 자동 통과, 초과 시 발송 잠금+결재 생성) → 3 발송·추적(열람 카운트) → 4 계약 확정(수락 웹훅→계약 등록) → 5 결제 안내 발송(glovek 딥링크/이메일/계약서·이체 선택) → 6 결제 확인(웹훅 자동/수기)→**상태 전진 연쇄 5단계** 자동 실행. 상단 요약 칩 스트립으로 전체 흐름 개관 | 돈은 glovek이 받고, 확인은 자동으로 온다 |
| ⑥ 결재 f-drop | 드랍 요청 → 결재 생성 → 파트장 승인 → 원 액션 자동 실행 | 권한 없어도 막히지 않음 |
