## 2. 남은 한 단계 ← **이것만 하면 켜집니다**

기존 Gmail 수집이 쓰는 **서비스계정을 그대로 재사용**합니다.
그 서비스계정은 이미 **도메인 위임(domain-wide delegation)** 으로 직원 계정을
대신하도록 설정돼 있고, Gmail 스코프만 허용돼 있습니다.

### Workspace 관리자가 할 일 (1건)

관리 콘솔 → 보안 → API 제어 → **도메인 전체 위임** → 해당 서비스계정의
클라이언트 ID 에 아래 스코프를 **추가**합니다.

```
https://www.googleapis.com/auth/spreadsheets
```

기존 Gmail 스코프는 그대로 두고 **추가만** 합니다.

### 왜 이 방식인가

- 새 서비스계정을 만들어 시트를 공유하면 **비공개 원장의 열람 범위가 넓어집니다.**
  이 방식은 서비스계정이 **시트 소유자 본인을 대신해** 접근하므로
  **시트 공유 설정을 전혀 바꾸지 않습니다.**
- 드라이브 전체 권한(`drive`)은 요구하지 않습니다. 시트 하나만 다룹니다.

### 환경변수 (값은 이 문서에 적지 않습니다)

| 이름 | 용도 | 현재 |
|---|---|---|
| `GOOGLE_SA_KEY_JSON` | 기존 서비스계정 키 (Gmail 과 공용) | **이미 설정됨** |
| `SHEETS_SYNC_SUBJECT` | 대행할 계정 = 시트 소유자 | **설정 필요** |
| `SHEETS_LEDGER_SPREADSHEET_ID` | 위 스프레드시트 ID | **설정 필요** |
| `SHEETS_LEDGER_TAB` | 기본 `유입·커뮤현황` | 선택 |
| `SHEETS_LEDGER_LOG_TAB` | 기본 `갱신기록` | 선택 |
| `CRON_SECRET` | cron 인증 (기존) | 이미 설정됨 |

셋 중 하나라도 비면 **아무것도 쓰지 않고 멈춥니다**(fail closed).

`migrations/0115_sheet_sync_runs.sql` 을 `/settings` 에서 적용하세요.

## 3. 켤 수 없을 때의 대안 (승인 없이 진행하지 않음)

위임 스코프 추가가 불가능하면, **소유자 본인이 실행하는 Apps Script 시간 트리거**
방식이 있습니다. 이 경우에도 공개 URL 은 만들지 않습니다.

1. admin 에 `CRON_SECRET` 으로 보호된 읽기 전용 export 엔드포인트를 둡니다
   (현재 cron 라우트가 그 역할을 겸할 수 있습니다).
2. 시트 소유자가 Apps Script 에서 그 URL 을 호출해 값을 씁니다.
   스크립트는 **소유자 권한으로** 돌아가므로 공유 범위가 넓어지지 않습니다.
3. 토큰은 Script Properties 에 둡니다.

**무인증 공개 export 는 만들지 않습니다.** 원장에는 연락처·매출이 들어 있습니다.

## 5. 안전장치 — 바꾸기 전에 읽어 주세요

- **메모 칸(`메모(직접입력)`)은 절대 쓰지 않습니다.** `PROTECTED_HEADERS` 에 있습니다.
- **우리가 모르는 열은 건드리지 않습니다.** `MANAGED_HEADERS` 에 적힌 열만 씁니다.
- **행을 지우지 않습니다.** 원장에서 사라진 브랜드의 행도 그대로 둡니다.
- **`브랜드ID` 열로 기존 행을 찾습니다.** 시트를 정렬해도 안전합니다.
  헤더 이름으로 열 위치를 찾으므로 열 순서가 바뀌어도 됩니다.
- **RAW 쓰기 + 선행 `'` 보강.** Sheets 안에서도, CSV 로 내려받아 다른 프로그램에서
  열어도 수식이 되지 않습니다.
- **빈값과 0 을 구분합니다.** 모르는 값은 빈칸이 아니라 `미확인` 입니다.
- **전화번호는 문자열입니다.** 앞의 0 이 사라지지 않습니다.
- **하루 한 번.** `(시트, KST 날짜)` 유니크 선점으로 겹침을 막습니다.
  실패한 날은 다시 시도되고, **실패가 지난 성공을 지우지 않습니다.**
- **갱신기록은 성공한 뒤에만** 씁니다.
- **로그·응답에 연락처·매출·토큰을 남기지 않습니다.** 건수와 상태만 남깁니다.

## 6. 매출을 다루는 규칙 — 섞지 않습니다

세 가지를 **같은 칸에 절대 넣지 않습니다**:

| 구분 | 출처 | 시트 표기 |
|---|---|---|
| ① 고객 신고 구간 | `weekly_onb_applications.revenue_band` | `고객 신고 구간` |
| ② AI 추정 | `brands.revenue_estimate` (0114) | `AI 추정 · 미확정 (신뢰도 X)` |
| ③ 우리 회사 수금액 | 결제·구독 | **넣지 않습니다** (브랜드 연매출이 아님) |

- 우선순위는 **① > ② > 미확인** 입니다.
- **AI 추정을 확정 실적으로 쓰지 않습니다.** 칸 안에 "미확정"을 적습니다.
- 근거가 없으면 빈칸이 아니라 `미확인` + 사유(`추정 전`/`추정 대기`/`확인 필요`)를 적습니다.
- **유료 AI 조사를 새로 돌리지 않습니다.** 이미 저장된 값만 읽습니다.
- 신고 구간은 **이메일 정규화 정확일치**로만 잇습니다. 추측 매칭을 하지 않습니다.

열: `T 매출액·구간` `U 매출기준·확인상태` `V 매출출처` `W 매출기준연도` `X 매출통화`

## 7. 커뮤니케이션 판정 — 단정하지 않습니다

`email_messages`(Gmail 수집) + `brand_emails`(수기·연동) 를 **브랜드별 전체** 집계합니다.
(기존 UI 가 최근 200스레드만 보던 것과 다릅니다.)

| 상황 | 표기 |
|---|---|
| 수신이 가장 최근 | `고객 회신 있음` |
| 수기 접촉이 가장 최근 | `담당자 직접 접촉` |
| 발신이 최근이고 이전 수신 있음 | `발신 후 대기(이전 회신 있음)` |
| 발신만 | `발신만 · 회신 없음` |
| 아무 기록 없음 | `기록 없음` |

**자동 안내가 나간 것을 고객 회신으로 치지 않습니다.**
`최근접촉표시` 에 근거 건수(`메일 N건`)를 함께 적습니다.

## 9. 날짜 서식에 대한 판단

현재 날짜는 **글자**(`2026-10-29 09:00`)로 씁니다.

기존 960행의 날짜 칸 서식을 이 환경에서 확인할 수 없어, 시리얼 숫자로 바꾸면
서식이 다른 기존 행과 섞여 표시가 깨질 수 있다고 보았습니다.
시트 날짜 칸 서식을 확정한 뒤 `lib/ledger-sheet-rows.ts` 의

```ts
export const DATE_AS_SERIAL = false;   // → true
```

하나만 바꾸면 진짜 날짜 타입으로 들어갑니다. 숫자 칸(매출기준연도)은 이미 숫자입니다.
