## 3. 권한 — 최소권한 경로 (기본값)

**기본은 서비스계정 자기 자신으로 동작합니다**(JWT `iss`=서비스계정, `sub` 없음).
그리고 **이 스프레드시트 한 개에만** 그 서비스계정을 **편집자**로 공유합니다.
권한 범위가 이 파일 하나로 끝납니다.

- 새 서비스계정·새 키를 만들지 않습니다. 기존 `GOOGLE_SA_KEY_JSON` 을 그대로 씁니다.
- **도메인 전체 위임(DWD)에 `spreadsheets` 스코프를 새로 추가하지 않습니다.**
  그건 "조직 모든 사용자의 모든 스프레드시트를 대신 열 수 있는 권한"이어서,
  시트 한 개 공유보다 훨씬 넓습니다. 이전 판 문서가 이 길을 권했던 것을 바로잡았습니다.
- 서비스계정 **이메일은 비밀값이 아닙니다**(공유 대상으로 알려줘야 하니까).
  비밀키는 어디에도 싣지 않습니다.

### 공유할 대상 주소를 어떻게 확인하나

운영 환경에서 `GOOGLE_SA_KEY_JSON` 의 `client_email` 값입니다.
코드에서는 `sheetsAuthState().clientEmail` 로 읽을 수 있습니다(비밀키는 반환하지 않음).
**이 컨테이너에는 그 키가 없어 주소를 확인할 수 없었습니다.** 운영에서 확인한 뒤,
그 주소 하나만 시트 공유 대화상자에 "편집자"로 넣으세요.

### 대행(impersonation) 경로는 선택이며 기본이 아니다

`SHEETS_SYNC_SUBJECT` 를 설정하면 그 사용자를 대행합니다.
**기존 도메인 위임에 `spreadsheets` 가 이미 허용돼 있다고 확인된 경우에만** 쓰세요.
설정하지 않으면 그 경로는 아예 시도하지 않습니다.

### 환경변수 (값은 이 문서에 적지 않습니다)

## 5. 안전장치 — 바꾸기 전에 읽어 주세요

각 항목은 테스트로 고정돼 있고, 일부러 깨 보면 **그 항목의 테스트만** 깨집니다.

1. **메모 보호** — `PROTECTED_HEADERS`. 띄어쓰기가 다른 `메모 (직접입력)` 에도 걸립니다.
2. **기존 값 보호** — 우리가 모르는 값(`미기록`)으로 채워진 칸을 덮지 않습니다.
3. **행 삭제 없음** — 원장에서 사라진 브랜드의 행도 그대로 둡니다.
4. **모르는 열 보존** — 헤더에 없는 이름은 쓰지 않습니다.
5. **쓰기 전 중단** — 필수 열 누락 / 같은 열 이름 중복 / 시트 안 브랜드 ID 중복이면
   **한 칸도 쓰지 않고** 실패로 돌립니다.
6. **쓴 뒤 확인(readback)** — `수집시각` 열을 다시 읽어 이번 실행 값이 실제로
   들어갔는지 셉니다. 기대보다 적으면 **성공으로 표시하지 않습니다**.
7. **겹침 방지** — 같은 (시트, 날짜)를 DB 가 하나만 통과시킵니다.
   `running` 은 `force` 로도 빼앗지 못합니다. 30분(`RUNNING_STALE_MINUTES`)을 넘겨
   멈춰 있는 `running` 만 죽은 실행으로 보고 회수합니다.
8. **DB 오류를 성공으로 보지 않음** — 선점 질의가 터지면 "이미 끝났다"가 아니라 실패입니다.
9. **부분 실패를 삼키지 않음** — 실행 기록 갱신 실패·로그 탭 쓰기 실패는
   `warnings` 로 응답에 올립니다. 조용히 넘어가지 않습니다.
10. **소스 DB 읽기 전용** — 이 기능은 `brands` 에 쓰지 않습니다.
11. **인증 fail closed** — 설정이 없으면 시트에 접근조차 하지 않습니다.
12. **로그에 개인정보 없음** — 응답·로그는 건수와 상태만 담습니다.

## 6. 매출을 다루는 규칙 — 섞지 않습니다

이 열이 말하는 매출은 **영업 대상 회사의 매출**입니다. 큰 팀·기업을 가려내기 위한
숫자이므로, 성격이 다른 값을 같은 칸에 넣으면 영업 판단이 틀어집니다.

| 종류 | 어디서 | U(기준·확인상태) 표기 | 회사매출 하한/상한 |
|---|---|---|---|
| ① 브랜드 자체 신고 | weekly 신청서(이메일 **정확일치**) | `브랜드 자체 신고 · 최근 12개월 자기신고(확정 회계연도 아님) · 회사 연매출 아님` | **미확인**(승격 금지) |
| ② AI 추정 · 회사 별도 | `brands.revenue_estimate`, scope=company_separate | `AI 추정 · 미확정 · 회사 별도 연매출 · 대상 {회사명} · 신뢰도 X` | **숫자** |
| ③ AI 추정 · 회사 연결 | 같음, scope=company_consolidated | `… 회사 연결 연매출 · 대상 {회사명} …` | **숫자** |
| ④ AI 추정 · 브랜드 단위 | 같음, scope=brand | `… 브랜드 단위(회사 연매출 아님) …` | **미확인**(승격 금지) |
| ⑤ 근거 없음 | — | `추정 전` / `추정 대기` / `확인 불가` 등 | 미기록 |
| ⑥ 우리 회사 수금액 | 결제·구독 | **범위 밖. 넣지 않습니다** | — |

- **U~X 에 회사명(entity)·범위(scope)·연도·통화를, V 에 근거 URL 을 남깁니다.**
  숫자만 보면 "브랜드 하나"인지 "법인 전체"인지 알 수 없어 뜻이 달라집니다.
- **①의 기준연도 칸에 연도 숫자를 넣지 않습니다.** 신청서 문항이 "최근 12개월"이라
  연도만 적으면 결산 매출로 읽힙니다. `최근 12개월 (신고 2026-09)` 처럼 적습니다.
- 숫자 확정이 없으면 **미확인**입니다. 빈칸으로 두지 않습니다.
- **유료 AI 조사를 새로 돌리지 않습니다.** 이미 저장된 값만 읽습니다.

### 정렬용 두 열 — `회사매출 하한` / `회사매출 상한`

금액으로 정렬·필터하려면 글자가 아니라 숫자가 필요합니다. 그래서 두 열을 **옵션으로**
지원합니다. 지금 운영 시트(A:X)에는 없으므로 **건너뜁니다** — 헤더를 추가하면
다음 실행부터 채워집니다.

- **회사 범위(별도/연결) 추정일 때만 숫자가 들어갑니다.**
- 브랜드 단위 추정과 브랜드 자기신고는 **미확인**입니다. 회사 매출로 승격하지 않습니다.
- 추정이라는 사실은 U 열이 계속 말합니다 — 숫자가 있다는 게 확정을 뜻하지 않습니다.

**이번 작업에서는 시트를 건드리지 않았습니다.**

### 갱신기록 탭 (A:H) — 시트에 있는 순서 그대로

`기록시각(KST)` · `원장건수` · `추가건수` · `변경건수` · `메일확인 업체` ·
`실행상태` · `기록 기준` · `원본`

실행 전에 이 헤더를 읽어 모양을 확인합니다. 다르면 **쓰지 않고 경고를 올립니다**
— 숫자가 엉뚱한 열에 들어가는 것이 빈칸보다 나쁩니다.

## 9. 날짜·전화 형식에 대한 판단

- **날짜는 숫자(시리얼)로 씁니다.** A·J 열이 이미 숫자 시리얼이고 표시 서식이
  `yyyy-mm-dd hh:mm` 입니다. 글자를 넣으면 한 열에 숫자와 글자가 섞여 정렬·필터가 깨집니다.
- 시리얼은 **분 단위로 끊습니다**. 같은 시각이 항상 같은 값이 되어 readback 비교가 흔들리지 않습니다.
- **G·O 열은 서식을 한 번 지정해야 합니다.** 우리가 새로 채우는 열이라, 서식이
  일반(General)이면 `46325.5` 처럼 숫자로 보입니다. 시트에서 G·O 열을 선택해
  **A열과 같은 날짜 서식(`yyyy-mm-dd hh:mm`)** 을 한 번 적용하세요.
  코드로 서식을 바꾸지 않습니다(요청 범위를 넘고, 기존 서식을 건드릴 위험이 있습니다).
- **전화번호는 원문 문자열입니다.** 숫자만 남기면 `+82` 와 내선이 사라져 다른 번호가 됩니다.
  RAW 쓰기라 `010...` 의 앞 0 도 살아 있습니다.
- **브랜드 링크(S열)는 링크처럼 보이는 것만 링크로 씁니다.** 원본 960건 중
  형식상 URL·도메인 398건, 빈값 436건, 이메일·"제작중"·설명문 126건입니다.
  http(s) 주소와 정상 bare 도메인만 정규화하고(bare 도메인에는 `https://` 만 붙임),
  나머지는 `URL확인필요`, 빈값은 `미기록` 으로 표시합니다.
  **값에서 도메인을 추측해 만들지 않습니다** — 없는 사이트를 적는 것보다 "확인 필요"가 낫습니다.
  자격증명이 박힌 주소(`user:pass@`), http(s) 가 아닌 스킴(`javascript:`·`data:`),
  수식으로 읽히는 글자로 시작하는 값은 링크로 쓰지 않습니다.
- **값 앞에 작은따옴표를 붙이지 않습니다.** 쓰기가 RAW 라서 `=`·`+` 로 시작하는 글자도
  수식이 되지 않습니다. RAW 에서 따옴표는 값의 일부로 저장되어 `+82...` 가
  `'+82...` 로 **망가집니다**. 수식 주입 방어는 RAW 쓰기 자체입니다.

## 12. 스냅샷 조회 경로 — 권한 승인 전 검증용

`GET /api/admin/sheets-ledger/snapshot`

Google 시트 권한이 승인되기 전에, **시트에 들어갈 값을 그대로** 눈으로 확인하기
위한 읽기 전용 경로입니다. 기존 로그인 브라우저로 바로 열 수 있습니다.

- **로그인 세션만** 받습니다. cron 토큰·쿼리 토큰 경로를 두지 않았습니다.
- **`role=exec` 만** 통과합니다(미로그인 401 / 다른 역할 403). `lead` 도 막습니다.
- `no-store` — 캐시에 남지 않습니다.
- `readLedger` + `buildRow` 를 **그대로 재사용**합니다. 그래서 응답의 행 키는
  시트에 쓰기로 승인된 열 이름뿐이고, **은행·서류·비밀번호·토큰은 담기지 않습니다**
  (테스트로 고정).
- 쓰기가 없습니다 — 시트도 DB 도 건드리지 않습니다.

응답: `count`, `scope`, `fields`, `rows`, `meta`.

`meta.serviceAccountEmail` 은 **이 시트 한 개에 편집자로 공유할 대상 주소**입니다.
서비스계정 이메일은 비밀값이 아니므로 exec 에게만 보여 줍니다.
**비밀키·액세스 토큰·도메인 위임 클라이언트 ID 는 어떤 경우에도 출력하지 않습니다.**

`meta.runtimeHas*` 는 **이 응답을 만든 런타임** 기준입니다. Cloud 컨테이너에서
`false` 로 보이는 것이 운영에 없다는 뜻이 아닙니다 — 이름을 그렇게 붙여 두었습니다.

> 현재 확인된 사실: Production Vercel 에 기존 서비스계정 키가 있고, 대상
> `SHEETS_LEDGER_SPREADSHEET_ID` 가 저장돼 있습니다. **별도 권한 부여·DWD 확대는
> 하지 않았습니다.** 정확한 서비스계정 주소를 확인한 뒤 이 시트 한 개의 writer
> 승인만 요청할 계획입니다. **아직 운영 연동 완료가 아닙니다.**

### 왜 원인을 못 봤나 — cron 이 결과를 로그에 남기지 않는다

`/api/cron/sheets-ledger` 는 실패 사유를 응답 JSON 으로만 돌려줍니다. Vercel Cron
로그에는 상태 코드만 남아, 운영에서 사유를 읽을 방법이 없었습니다.

### 이번에 추가한 진단 두 가지

**① snapshot 에 최신 실행 감사 상태 한 건**
`GET /api/admin/sheets-ledger/snapshot` 응답의 `latestRun` 에
`status` · `runDate` · `attempts` · `brands` · `updatedRows` · `appendedRows` ·
`startedAt` · `finishedAt` · `error` 가 들어갑니다.

- 쿼리는 `env.sheets.ledgerSpreadsheetId` **한 시트로 한정**한 `queryOne` 고정 SELECT 입니다.
- 표가 없거나 조회가 실패하면 `{ available: false, unavailable: "..." }` 로 **명시**합니다
  — 없는 것을 성공으로 보지 않고, DB 예외 문구도 옮기지 않습니다.
- 기록이 아예 없으면 `선점 전 중단` 입니다. 그 자체가 단서입니다:
  인증·마이그레이션 단계에서 멈췄다는 뜻이고, `meta.sheetWriteReady` 와 함께 읽으면
  어느 단계인지 좁혀집니다.
- 연락처·매출·키·토큰을 담는 필드가 없습니다(테스트로 고정).

**② 403 을 ACL 로 단정하지 않는다**
Google 403 은 사유가 세 갈래입니다 — **서비스 미활성 / API 권한 / 파일 공유(ACL)**.
전부 ACL 로 적으면 이미 승인된 공유 권한을 다시 들여다보게 됩니다.
이제 응답 본문에서 `error.details[].reason` 의 **허용된 코드만** 읽어 분류합니다:

| reason | 분류 |
|---|---|
| `SERVICE_DISABLED` | 서비스 미활성(프로젝트에서 API 사용 설정 필요) |
| `API_KEY_SERVICE_BLOCKED` | API 권한(사용 차단) |
| `ACCESS_TOKEN_SCOPE_INSUFFICIENT` | API 권한(스코프 부족) |
| `ACCESS_TOKEN_EXPIRED_INVALID` | 토큰 만료·무효 |

허용 목록에 없는 코드나 사유가 없는 403 은 **단정하지 않고** 세 갈래를 모두 말합니다.
원문 `message` 와 `metadata` 값은 **읽지도 남기지도 않습니다**(토큰·주소·프로젝트
번호가 섞일 수 있습니다). 사유 코드 자체는 고정 열거값이라 응답에 남깁니다.

### 다음에 할 일

1. `GET /api/admin/sheets-ledger/snapshot` 을 exec 세션으로 열어 `latestRun` 을 읽습니다.
2. `latestRun.error` 가 403 이면 위 표로 분류가 바로 나옵니다.
   `unavailable: 선점 전 중단` 이면 인증·마이그레이션 단계이므로 `meta` 를 함께 봅니다.
3. 사유가 확인되면 **그 한 가지만** 고칩니다. 권한·스코프를 넓히지 않습니다.

### 아직 남은 문제

- **cron 자체는 여전히 결과를 로그에 남기지 않습니다.** 이번 범위에 cron 라우트
  변경을 넣지 않았습니다. `latestRun` 으로 사후 확인은 되지만, 선점 전에 멈춘

- 시트 G·O 열 날짜 서식 적용 여부 미확인.
- `상태표시` · `회사매출 하한/상한` 열은 시트에 없어 건너뜁니다.
